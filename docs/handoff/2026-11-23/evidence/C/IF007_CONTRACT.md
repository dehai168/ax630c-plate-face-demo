# 十字段合同（classify_color 函数主体，执行前冻结）

不改 `2241e28`，不改六文件，不做完整应用构建，不跑模型、NPU 或视频。不改颜色预处理策略。不发 PR，不合并。

现有 `tools/test_rules.cpp` 不调用 `classify_color`。该函数是 private，不能单独链接。本轮从 `src/plate_rec.cpp` 抽出原文，不重写语句。

1. 问题：长度 5 误接到实际 `classify_color` 主体时，是否确实不读错误的前三个值，而走既有 HSV。
2. 证据：`2241e28` 只有 `outs[0].size() == 3` 这一处相对旧谓词的改动。此前的 stdlib 程序只测了条件本身，没有测函数返回值、置信度或 HSV。
3. 单假设：同一原文主体对合法长度 3 给出与旧主体（`>= 3`，且只在长度恰好为 3 时调用）相同的颜色和置信度；对非 3、空输出、`run` 失败，以及 `cls_` 为空，结果与 `cls_` 为空的 HSV 回退一致。
4. 机制：编译未改的函数主体。HSV 计算就在该函数内部，没有另立的 helper。用 mock `InferEngine` 返回预先写好的 tensor，输入是固定 BGR 纯色 `cv::Mat`。不加载 ONNX、axmodel，也不访问外部服务。
5. 区别：覆盖的是函数分支，不是再跑谓词小程序，也不是 176、32 或 42。不测颜色准确率。
6. 数据：执行前冻结，之后一次跑完，不按结果换样。四张 96×96：纯蓝 `(255,0,0)`、纯绿 `(0,255,0)`、纯黄 `(0,255,255)`、灰 `(128,128,128)`。合法长度 3 的 shape 为 `{1,3}`，三个高置信模式 `{0.95,0.03,0.02}`、`{0.03,0.95,0.02}`、`{0.02,0.03,0.95}`，再加一个低置信 `{0.50,0.30,0.20}`。非法逻辑长度 0、1、2、4、5、6、12，缓冲里放 `{0.99,0,0,...}` 但 shape 乘积不是 3。另有 `run` 返回 true 且 outs 为空，以及 `run` 返回 false 但 outs 里仍留下长度 3 的高置信蓝。`cls_` 为空是对照，不是额外挑选的样本。合计断言 4×4 个合法对照 + 4×7 个非法长度 + 4 个空输出 + 4 个 run 失败 = 52。
7. 期望：合法 3 上，新主体与旧主体的 `color` 和 `conf` 用 `==` 比较。非法长度、空输出和 run 失败不看 tensor 里的数，只要求与同一张图上 `cls_` 为空的结果一致。
8. 风险：mock 不是 AX 或 ORT。private 成员只做作用域适配。不覆盖 NPU2、padding 字节或应用视频。
9. 预算：2 CPU、2 GiB、5 分钟。沿用已安装的 OpenCV。只编译这个 harness。不新增依赖，不跑模型、ORT 或量化。
10. 成功、失败、早停：记录函数体字节哈希、起止行和 adapter diff。adapter 只去掉 `PlateRecognizer::` 并把同名 `cls_`、`cls_in_` 放进最小类。失败则报告，不改算法、不改夹具。编译不成则停，标未测，不用谓词小程序代替。通过只表示 `ACCEPT_OFFLINE_FUNCTION_MOCK_ONLY`。

旧主体只把该行的 `== 3` 换成 `>= 3`，并且只在逻辑长度为 3 时调用。长度为 0、1、2、4、5、6、12 时不调用旧主体，避免按前三个 float 读取造成越界。
